# 个人密码库初始化与使用指南

适用版本：当前仓库中的 `vault-web` 前端，核对日期为 2026-10-16。以下步骤对应简体中文界面。

首次使用的完整顺序是：**系统账号登录 → 绑定并验证 Passkey → 备份并确认 MFA 恢复码 → 设置主密码 → 下载并验证两份密钥文件 → 完成初始化。**

**如果你已经进入「生成 MFA 恢复码」页面，可以直接从第 4 节开始，不用重新绑定 Passkey。**

当前版本仍处于测试账户联调阶段。修改主密码、备用 Passkey 管理、解密恢复、完整密钥轮换和加密备份恢复页面尚未开放；请先用测试数据完成下面的流程。

## 1. 打开密码库

密码库地址：[https://vault.local.muzhi.store](https://vault.local.muzhi.store)。

也可以在 ERP 中打开「个人密码库」菜单，再点击「打开个人密码库」。当前会在新标签页打开独立站点，不会在 ERP 内容区内嵌密码库。ERP 与密码库需要分别登录。

如果前端服务已经启动，直接打开页面即可，不要重复运行启动命令。

仅在需要自行启动密码库时，在项目根目录执行：

```sh
cd /Users/muzhi/WorkSpace/PersonalProject/Web/mini-erp-web
npm run dev:vault
```

保持该终端运行；按 Ctrl+C 会停止本次启动的密码库服务。浏览器仍使用上面的 HTTPS 域名，现有 NGINX 会将页面转发到本机 `8002` 端口。

如果 ERP 和密码库都没有运行，可以在根目录执行 `npm run dev:all` 同时启动。ERP 页面使用 `8000`，它的内部开发服务使用 `8001`，密码库使用 `8002`。不要同时用两种方式重复启动同一项服务。

如果出现「Port 8002 is not available」，说明已有进程占用该端口。先检查原来启动服务的终端；若已有密码库服务，直接访问页面，或在原终端按 Ctrl+C 停止后重新启动。不要为了绕过占用随意修改端口或域名。

如果 `dev:all` 因 ERP 的 `TurbopackInternalError` / `read was canceled` 退出，并带停密码库，请按 [README 中的构建缓存清理步骤](../README.md#development) 处理后重新启动。

## 2. 先分清这些名称

| 名称 | 从哪里获得或怎么填写 | 用途 |
| --- | --- | --- |
| 系统账号、系统登录密码 | 使用现有系统账号及其登录密码 | 登录密码库站点，确认你是哪个账号 |
| Passkey 名称 | 自定义备注，例如「我的 MacBook」 | 帮助识别这次绑定的通行密钥，不是密码 |
| Passkey（通行密钥） | 点击「绑定 Passkey」，按浏览器或系统弹窗创建 | 在系统登录后完成身份验证，不需要手动填写密钥内容 |
| MFA 恢复码文件 | 在恢复码页面生成并下载，默认名为 `vault-mfa-recovery-codes.json` | 无法使用原 Passkey 时恢复身份；不能解密密码库 |
| 主密码 | 创建密码库时自己设置 | 与账户密钥文件配合，在浏览器中解锁密码库；不会写入下载文件 |
| 账户密钥文件 | 创建密码库时下载，默认名为 `vault-account-key.json` | 日常解锁时选择此文件，并输入主密码 |
| 解密恢复文件 | 创建密码库时下载，默认名为 `vault-recovery-key.json` | 用于解密恢复的秘密材料；当前前端尚未开放使用它进行恢复的页面 |
| 条目密码 | 初始化完成后，为某个网站或账号保存的密码 | 这是密码库里保存的内容，与登录密码和主密码分别管理 |

三份 JSON 文件用途不同，不能互相代替。浏览器可能为重复下载的文件名加上 `(1)` 等后缀，选择时要确认是本次流程对应的文件。

## 3. 登录并完成 Passkey 验证

### 3.1 登录密码库

在「登录密码库」页面填写：

1. **账号**：现有系统账号。
2. **系统登录密码（不是主密码）**：这个账号原有的登录密码。
3. 点击「登录密码库」。

此时不要填写尚未创建的主密码。

### 3.2 第一次使用时绑定 Passkey

在「身份验证」页面：

1. 在「Passkey 名称」填一个自己能识别的备注，例如「我的 MacBook」。
2. 点击「绑定 Passkey」。
3. 按浏览器或系统弹窗完成通行密钥创建；实际确认方式由设备和浏览器提供。
4. 绑定成功后，如果仍在身份验证页面，点击「验证 Passkey」。
5. 按弹窗完成验证。

**创建 Passkey 和验证 Passkey 是两个操作。只填名称、只完成绑定，都不等于已经完成身份验证。**

如果以前已经绑定过本域名的 Passkey，这次直接点击「验证 Passkey」，不需要再绑定一个。

这一页下方的「一次性 MFA 恢复码」供遗失 Passkey 后恢复身份使用。首次绑定和正常验证时留空，不用点击「恢复身份并重新绑定」。

成功后，首次使用会进入第 4 节的恢复码备份页；已经完成恢复码确认的账号可能直接进入创建或解锁密码库页面。

## 4. 生成、下载并确认 MFA 恢复码

「生成 MFA 恢复码」页面用于备份身份恢复手段，和创建 Passkey 是两件事。

按顺序操作：

1. 点击「生成 MFA 恢复码」。
2. 生成成功后，页面会出现下载、重新导入和确认操作。
3. 点击「下载 MFA 恢复码文件」，确认文件已实际下载。
4. 在「重新导入刚下载的 MFA 恢复码文件」处，选择刚下载的 `vault-mfa-recovery-codes.json`。
5. 点击「确认保管并继续」。

重新导入时选择完整 JSON 文件即可，不需要打开文件、复制里面的代码或手动填写 JSON 字段。页面会核对文件是否与本次生成的恢复码一致。

**看到下载文件不代表这一步完成；必须点击「确认保管并继续」，并成功进入下一页。**

文件中包含一批一次性恢复码。以后确实无法使用原 Passkey 时，才在身份恢复输入框中使用其中一条；初始化时不用在那里逐条填写。

### 4.1 已经生成过，为什么又只剩「生成」按钮？

当前前端只在本页内存中保存待确认的恢复码。刷新、关闭页面、自动锁定或切换界面语言后，这份临时记录会被清除。

如果你已生成过 MFA 恢复码，但页面再次只显示「生成 MFA 恢复码」：

1. 当前版本没有从旧下载文件直接接续确认的入口。
2. 重新生成一批。
3. 下载新的文件，重新选择这份新文件，再确认。
4. 新一轮确认成功后，保管最终有效的文件，避免之后选错旧批次。

重新生成会撤销此前尚未确认的批次。不要将旧批次文件与新批次混用；这个操作不会要求你重新绑定已经可用的 Passkey。

### 4.2 提示需要重新验证身份怎么办？

后端要求生成、确认恢复码时，最近一次 Passkey 验证在 5 分钟内；待确认批次本身也有 10 分钟的确认期限。因此这一段应连续完成。

如果提示需要近期认证：有「验证 Passkey」按钮时先验证；如果恢复码页面没有这个按钮，点击顶部「退出密码库」，重新登录，再验证已有 Passkey，然后继续生成、下载、导入和确认。无需重新绑定 Passkey。

## 5. 创建密码库

完成 MFA 恢复码确认后，尚未初始化的账号会显示「创建密码库」。

### 5.1 设置主密码

1. 在「主密码」输入你为密码库新设置的密码。
2. 在「再次输入主密码」完整输入同一个密码。
3. 点击「生成密钥与文件」。

主密码要求：

- 至少 16 个 Unicode 字符，最多 1024 个 UTF-8 字节。
- 使用与系统登录密码不同的主密码。
- 大小写和空格都会影响结果；当前实现不会自动去掉首尾空格或进行大小写转换。
- 自行记住并妥善保管，下载文件里不会保存主密码。

点击生成后，页面会进行本地加密计算。等待当前操作结束，不要反复点击或刷新页面。

### 5.2 下载两份密钥文件

页面出现文件操作后，分别点击：

1. 「下载账户密钥文件」：保存 `vault-account-key.json`。
2. 「下载解密恢复文件」：保存 `vault-recovery-key.json`。

这是两份新的文件，不是第 4 节的 MFA 恢复码文件。此时你应该一共保管三类文件：MFA 恢复码文件、账户密钥文件、解密恢复文件。

### 5.3 重新导入两份文件并验证

1. 在「重新导入账户密钥文件」处选择本次下载的 `vault-account-key.json`。
2. 在「重新导入解密恢复文件」处选择本次下载的 `vault-recovery-key.json`。
3. 点击「验证两份文件」。
4. 等待页面显示「文件已验证」。

两处都要先点击对应的下载按钮，文件选择控件才会启用。必须选中本次生成的两份匹配文件，不要拿 MFA 恢复码文件或之前未完成初始化时下载的旧文件代替。

这里的重新导入是在浏览器中读取和核对本机文件。账户密钥、解密恢复密钥和主密码不会作为明文提交给后端。

### 5.4 提交初始化

1. 两份文件验证通过后，点击「完成初始化」。
2. 等待页面切换到「密码条目」。
3. 能看到「添加条目」按钮，说明这次初始化与本次解锁流程已完成。

**只生成文件或只看到「文件已验证」都还不算完成初始化，最后还要提交。**

## 6. 验证初始化结果

先保存一条测试数据，再做一次锁定和解锁验证。

### 6.1 保存一条测试条目

1. 点击「添加条目」。
2. 标题填「初始化测试」。
3. 网址可填 `https://example.com`，账号填测试用备注。
4. 密码使用测试值，或点击「生成 24 位随机密码」。
5. 点击「保存」，确认条目出现在列表中。

标题必填；网址如果填写，需要包含 `http://` 或 `https://`。其他字段可按需要填写。

### 6.2 做一次锁定与解锁验证

1. 点击顶部「锁定」。
2. 出现「解锁密码库」后，在「账户密钥文件」处选择最终初始化成功时对应的 `vault-account-key.json`。
3. 输入刚才设置的主密码。
4. 点击「解锁密码库」。
5. 确认「初始化测试」条目仍在列表中，并可使用「短暂显示」查看。

这一步用于核对自己保管的账户密钥文件和主密码确实可以解锁。**MFA 恢复码文件和解密恢复文件都不能填到账户密钥文件的位置。**

## 7. 以后每次怎么进入

日常完整进入流程为：

1. 打开同一个密码库 HTTPS 域名。
2. 如果要求登录，输入系统账号和系统登录密码。
3. 如果要求身份验证，点击「验证 Passkey」，使用已有通行密钥。
4. 在解锁页选择 `vault-account-key.json`。
5. 输入主密码，点击「解锁密码库」。

如果服务端登录会话和 MFA 仍有效，页面可能直接显示解锁页。正常使用不需要每次重新绑定 Passkey、生成 MFA 恢复码或创建密码库。

当前版本锁定或刷新后都需要重新选择账户密钥文件。账号登录成功、Passkey 验证成功与本地解锁分别对应不同步骤。

## 8. 中途刷新或自动锁定，怎么继续

当前页面在持有临时秘密或已解锁时，会在无操作 5 分钟、或进入后台 60 秒后锁定；刷新、离开页面、手动锁定和切换语言也会清理本页秘密状态。另一标签页发出的锁定或退出消息也可能触发清理。

操作前先读完当前步骤，再连续完成下载、选择文件和确认，避免反复切换到其他页面超过后台期限。

| 中断时所在步骤 | 继续方式 |
| --- | --- |
| Passkey 已绑定，尚未完成验证 | 使用已有 Passkey 点击「验证 Passkey」，不用重新绑定 |
| MFA 恢复码已生成，但尚未确认，页面临时记录已清除 | 按第 4.1 节重新生成、下载、导入和确认 |
| 已生成两份密钥文件，但尚未提交初始化，临时草稿已清除 | 若仍显示「创建密码库」，重新设置主密码并生成一套新的匹配文件，再验证和提交；此前未提交草稿的文件不能与新文件混用 |
| 点击过「完成初始化」，但没有看到结果 | 先重新连接页面并查看当前状态；出现「解锁密码库」时，使用那次提交对应的账户密钥文件和主密码，不要假定初始化失败后重新创建 |
| 已初始化并进入条目列表后锁定 | 重新选择账户密钥文件、输入主密码并解锁；已保存到后端的条目不会因本页锁定被删除 |
| 正在编辑条目时进入后台 | 当前实现会立即关闭编辑窗口；未保存内容不会自动恢复 |

如果初始化提交报错，但当前草稿和文件仍保留，先处理错误，再使用原有草稿重试「完成初始化」。前端会先查询当前初始化状态；不要在结果尚未确认时随意重新生成密钥。

## 9. 三份文件怎么保管

| 文件默认名 | 保存要求 | 后续使用位置 |
| --- | --- | --- |
| `vault-mfa-recovery-codes.json` | 保管最终确认有效的批次；包含可用于身份恢复的一次性秘密 | 遗失 Passkey 时，从中取一条有效恢复码，在身份恢复输入框使用 |
| `vault-account-key.json` | 保存最终初始化成功对应的文件；不要只保存在即将关闭的浏览器页面里 | 日常「解锁密码库」的账户密钥文件选择框 |
| `vault-recovery-key.json` | 单独保管，不要与账户密钥混淆；它是秘密恢复材料 | 当前前端尚未提供解密恢复操作页面 |

将这些文件当作秘密材料保管，不要提交到 Git、粘贴到聊天或发给别人。按页面要求分别离线保管账户密钥和解密恢复文件，主密码另行妥善保管。不要把它们只存进这个尚待解锁的密码库，否则需要时可能无法取出。

JSON 文件无需手动修改。重新生成或下载过多次时，应明确标识哪一套对应最终成功的初始化，避免仅凭文件名判断。

## 10. 常见卡点

| 现象 | 原因或处理方式 |
| --- | --- |
| 刚进身份验证页，看起来每个输入框都有必填标记 | 页面包含正常验证、首次绑定和身份恢复三条路径，只填写自己正在使用的那条路径 |
| 登录后只显示状态提示和「重新同步」 | 正在读取密码库状态时先等待；失败后点击「重新同步」或错误提示中的「关闭提示 / 重新连接」重试。开发代码热更新后可完整刷新一次页面，不用重新初始化 |
| 已创建 Passkey，仍要求生成 MFA 恢复码 | 这是下一步身份恢复备份，两者不同，按第 4 节继续 |
| 已下载 MFA 恢复码，仍无法进入创建页 | 下载之后还要重新选择刚下载的文件，并点击「确认保管并继续」 |
| 「重新导入」控件不可用 | 先点击该文件对应的下载按钮；等待当前操作结束，再选择文件 |
| 「完成初始化」按钮不可用 | 两份密钥文件都要下载、重新导入，并点击「验证两份文件」直到显示「文件已验证」 |
| 文件无效 | 检查文件类型、账号以及批次是否对应；不要把三种 JSON 文件混用，不要改写文件内容 |
| 文件已验证，但提交时提示服务返回的数据格式异常 | 保留原有密钥文件和主密码，重新连接后查看状态；若出现解锁页，使用这次提交对应的账户密钥文件解锁，不要重新创建密码库 |
| 提示近期认证过期 | 按第 4.2 节重新验证 Passkey；恢复码页没有验证入口时，退出密码库后重新登录和验证 |
| 无法解锁 | 检查使用的是最终初始化对应的账户密钥文件，主密码是否完全一致，包括大小写和空格；MFA 恢复码无法代替主密码或账户密钥 |
| Passkey 弹窗取消或操作失败 | 回到页面重试对应的绑定或验证；使用此前保存通行密钥的设备或可访问该通行密钥的环境，不要反复新增绑定 |
| Passkey 遗失 | 登录后使用此前确认保存的一条有效 MFA 恢复码，进入身份重绑；之后仍需要账户密钥文件和主密码来解锁 |
| 主密码或账户密钥遗失，只剩解密恢复文件 | 当前前端尚未开放解密恢复页面，不能按已有页面直接完成恢复；不要把恢复文件当作账户密钥导入，也不要重新初始化覆盖现有密码库 |

## 11. 初始化完成核对

- [ ] 已绑定并成功验证一个 Passkey。
- [ ] 已下载 MFA 恢复码文件，并成功点击「确认保管并继续」。
- [ ] 已设置并妥善保管主密码。
- [ ] 已下载、分别保管账户密钥文件和解密恢复文件。
- [ ] 已重新导入两份密钥文件，并通过「验证两份文件」。
- [ ] 已点击「完成初始化」，进入「密码条目」页面。
- [ ] 已保存一条测试条目。
- [ ] 已完成一次锁定，再用账户密钥文件和主密码解锁，确认测试条目仍可读取。

完成以上步骤，才算跑通当前版本的首次初始化与日常解锁流程。当前尚未开放的解密恢复、主密码修改、完整密钥轮换和加密备份恢复功能不在这份操作流程内。
